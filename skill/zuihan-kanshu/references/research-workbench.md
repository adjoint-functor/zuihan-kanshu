# 研究稿工作台

用于持续数学研究。按当前研究需要阅读以下部分；文件操作集中在整合保存时完成。

内部研究推导、检索与核验阶段不加载中文模组。每轮收束、真正组织给用户的报告时使用 `writing-style.md`；报告预期为中文时，才按 `SKILL.md` 加载 `chinese-translation.md` 及其共享参考。若本轮已经加载，不据中文润色规则干预内部研究过程或数学判断，在报告阶段采用。文风只优化报告的组织、清楚、准确和自然，沿用既有简报长度、结构与详略，不自行压缩扩写，也不套用问答的自适应长度规则。正式研究仍维护下列五文件，不因语言指导增加文稿控制、全稿终审或成品轮次；暂停后只讨论所问，不自动开启新研究轮次。

## 项目与五文件

项目目录按 `SKILL.md` 的“执行与保存”约定确定：指定目录优先；具备 Work/Library 云端保存能力时，新项目默认放在 Library 根目录的 `瑞般观珠/` 下，优先使用用户明确的项目名，否则自主按主题命名，首次保存确认实际目录；接续已有项目沿用原目录，不自动迁移。其他宿主按用户目的地和当前工作区的可用能力保存。

项目顶层维护一套同版本五文件：

- `<项目名>_数学主稿_vMAJOR.MINOR.PATCH.md`
- `<项目名>_计算草稿_vMAJOR.MINOR.PATCH.md`
- `<项目名>_研究日志_vMAJOR.MINOR.PATCH.md`
- `<项目名>_下一次入口_vMAJOR.MINOR.PATCH.md`
- `<项目名>_参考资料台账_vMAJOR.MINOR.PATCH.md`

`download/` 保存尚缺的文献；`tmp/` 保存候选与临时材料；`old/` 保存上一版完整五文件。日常恢复使用当前版本，只有追溯具体问题时才读历史。其他用户材料不随五文件切换。

计算型研究可将复现所需代码、数据、证书和环境另存版本化 `evidence/`，由草稿或台账指向具体输入、参数、误差界和终止条件。需要后续复阅的关键核验原始报告也可放在此处；长期记录引用的核验材料应有实际可重取的位置，无须保存全部探索输出。被取代的证据可移入 `old/evidence/`；仍支持当前结果的材料继续可用。

版本按实际内容选择：局部推进用 PATCH，新增研究轴或重组一组依赖用 MINOR，整体目标改变用 MAJOR。研究、回顾与维护可以包含相互关联的多项成果；版本数字不决定探索次数。

### 内容起草与写回

主代理统筹五文件的内容接纳、编辑安排和保存；实际研究者按 `research-roles.md` 交付可直接整合的论证与证据，不只交摘要。按需要分工，不为五个文件各设常驻代理：

| 文件 | 内容起草与主代理责任 |
|---|---|
| 数学主稿 | 证明者提供完整论证，也保留主代理或探索者构思中已完成的短论证；主代理确定接纳范围，统一结构、条件、状态与依赖。 |
| 计算草稿 | 实际研究者留下可复用推导、计算和失败经验；主代理确定本次整理范围，核对必要证据。 |
| 研究日志 | 根据实际成果与核验记录起草；主代理确认增量、改道理由和未决事项后追加。 |
| 下一次入口 | 主代理决定阶段目标、近期安排、完成尺度与恢复位置；辅助整理不代替这些判断。 |
| 参考资料台账 | 实际检索、阅读和使用文献的代理提供条目与依据；主代理确认书目信息和数学适用性状态准确。 |

较长证明的整理和章节重组可由主代理分派数学编辑者，职责与模型见 `research-roles.md`。候选修改经主代理验收后，可交给指定执行者或数学编辑者执行写回；每个共享文件或段落只有一个写入负责人，主代理核对最终文本和保存结果，不必亲自重敲正文。编辑中的数学疑点交回研究处理，核验者保留独立报告，不直接代写并接纳自己的修补。

### 数学主稿

唯一当前数学正文。按数学依赖组织目标、记号、定义、结果、证明、反例和开放问题，保持可独立阅读。可合并重复命题、修正失效导航，并用已建立的一般结果组织特例；保留证明、必要条件和仍被引用的锚点，或为移动内容给出明确指针。模板提供起草结构，章节可按实际数学重新组织，不以固定栏目名衡量完整性。按 mathematical-judgment.md 判断证据，使用以下状态表达：

- `【已建立】`：有完整推导，或已核对成熟文献的准确陈述和适用条件；
- `【条件成立】`：结论仍依赖明确列出的未证前提、未确认对象性质或其他未决依赖；已证明定理的正常适用假设本身不使它降为此状态；
- `【猜想】`：有依据但未证明；
- `【待验证】`：证明、计算或来源适用性仍有缺项；
- `【不成立】`：有明确否证，说明失效范围。

条件性结果与已建立结论清楚区分，并让实际使用它的后续结论继承未决依赖；没有相关内容时无需保留空栏目。主稿保存数学论证、依赖和开放问题；执行安排留在入口，过程留在日志。格式校验不能判断命题是否正确。

### 计算草稿

保存当前可复用的推导、试算、局部证明和失败经验，按数学对象与依赖组织，可删除、合并、压缩和重排。结果按数学独立价值划分，普通代数步骤留在证明内部。

只整理本次实际涉及的部分。已进入主稿的内容保留必要复核骨架和主稿指针；失败路线写明尝试、第一处障碍及值得重访的条件。“这种方法没有成功”与“命题为假”分别记录。没有保留价值的机械输出和旧任务清单可以清理，必要计算证据保留。

当前问题包按需引用主稿中的目标、允许假设、相关结果与实际问题；上下文已清楚时不另造重复问题包。草稿可写推导的局部待解步骤；研究安排以入口中的近期计划为准。

### 研究日志

每个发布版本完整复制旧日志，只在末尾追加一条短记录。记录目标与增量、关键改道或失败、必要核验结论与未决事项；常规操作和未发生事项无需逐项自证。稳定约定集中保留，不逐轮重述已退出的流程；数学假设、反例范围、不能交换的操作和用户明确边界仍准确保留。记录实际当地日期；旧日期错误在新记录勘误，历史前缀保留。

回顾时说明实际检查范围、路线判断和理由，可以同时记录新结果。

### 下一次入口

维护当前状态，而非积累历史任务。近期计划的统一存放位置是本文件的“当前近期计划”一节；总目标、当前可靠基础与前沿、必要读取位置和真实需要用户决定的问题也在入口中简记。

近期计划写清当前阶段要得到什么、怎样算完成，以及主代理据此选择的优先工作和理由。下一步是计划的一部分，不另维护一份平行待办；局部证明缺口只有被选为当前工作后才进入近期安排。阶段已完成、分支暂停或尚未选定后续任务时直接说明，不为填满入口追加任务。用简短段落或列表即可，不规定条目数或新增校验字段。长远候选只留必要方向与重访条件。

按总目标和新证据动态更新计划：可以重排、合并、替换或撤下已失去作用的任务。阶段达到原定完成尺度即收口；新发现的可选加强另列候选，不回填为该阶段的完成前置。后续是否继续取决于用户已授权的目标和轮次范围。改变用户目标、降低承诺的结论强度或解除用户明确暂停时询问；范围内的方法和顺序调整自主处理。

收到用户的规划决定或研究结果改变路线时，将当前安排落实到入口。日志仅追加调整理由与结果；草稿保存数学工作与必要指针；主稿保留数学目标和开放问题。旧文件中的散落计划按本次实际触及范围归并，不改写历史日志。临时计划工具不代替这个恢复位置。

入口可以列出当前五文件以便定位；需要重读时写“文件 → 标题、命题编号、节号或页码”，并自然说明用途。先定位结论及条件，再读取当前使用所需的证明和依赖；不要求每次同时读取主稿、草稿和台账。机器只校验明确的结构与可定位锚点，不用固定用途词猜测研究叙述。

入口保留当前恢复所需的信息，合并已被后续结果吸收的阶段概述，删去重复说明和失效导航；不按字符数裁剪必要数学条件、计划或用户约定。由模型结合用户目标和实际材料理解入口，按需更新当前计划与定位。

### 参考资料台账

记录书目信息、公开身份、当前用途、核验状态、勘误和定位。来源已核实且仍适用时复用该状态；重要适用条件变化时重新核对相应部分。执行过程留在日志，内部结果的详细依赖留在主稿证明附近，台账不重复整轮总结。文献使用与下载命名见 `literature.md`。

## 恢复与局部编辑

1. 确认当前项目、版本和是否有未完成候选。新环境根据实际目录恢复；仅在存在无法区分的目标时询问。
2. 可靠本地副本直接复用。缓存丢失或远端版本变化时，通过当前存储位置支持的方式取得完整文件字节；Work/Library 中按 Library 技能处理。不要先让模型读五个全文，也不要覆盖未保存的修改。
3. 先用已有有效上下文和入口恢复总目标、可靠成果、当前障碍及用户新指示，保留用户明确约定。主代理据此判断当前工作与现有计划，不只机械执行入口最后一条待办。已读且仍适用的内容继续复用，入口陈旧或材料变化时再补读相关结果和最近日志，把有效近期计划归并到新入口。
4. 用程序完整复制五文件建立下一版候选，再在旧文本上局部编辑。复制、上传完整字节不需要模型重新生成全文；五文件中只有日志要求保留整个文件的旧前缀。复制是编辑起点，其他文件可按当前数学整理本次涉及部分，不以节省 token 为由删去证明，也不把全历史清理设为研究前置。

## 自主研究与回顾

主代理按研究实际需要，结合已有有效上下文、入口与新证据判断当前工作并持续指导路线；信息充分时直接推进。已有且仍有效的证明、核验与计划继续复用，不因轮次切换重置。以用户目标和阶段完成尺度选择工作，能连贯完成的相关成果一起推进。角色、模型、探索及路线取舍见 `research-roles.md`；数学证据、核验意见与依赖变化见 `mathematical-judgment.md`。

重要结果返回或路线判断改变时，把主代理选定的当前工作更新到入口，区分必要依赖和可选加强。回顾可以嵌入当前轮，无需等待固定次数、逐项填表或另开纯回顾轮。条件性探索保留真实前提，局部失败后仍可推进无关的可靠成果。

需要人类选择研究目标、结论强度、相互冲突的优先级，缺少不可替代输入，或合理尝试后仍无可行下一步时，保存当前进展并提出具体问题、推荐选项和影响。普通方法选择与可修复障碍自主处理。用户主动暂停、局部分支结束、保存完成与整个数学目标完成分别表述；遵守用户明确的单轮和暂停要求。

## 整合、保存与归档

1. 主代理验收作者或编辑者的候选修改，按 `mathematical-judgment.md` 检查实际连接及未覆盖的论证，安排单一写入负责人将接纳内容写入候选主稿，保留准确条件和证据状态；整理相关草稿与台账。
2. 日志追加本次增量与实际改道理由，入口更新当前前沿和近期计划，移除已完成或失效的执行待办。检查五文件版本、日志完整前缀、明确引用与必要证据。已经通过且内容未变的检查无需重复。
3. 完成本地版本切换。使用宿主实际可用的保存方式，把完整新版五文件保存到已确定的项目目录；具备 Work/Library 云端保存能力时按 Library 技能处理，本地成功不代表远端已经保存。
4. 确认五个新文件的保存结果全部成功，再将上一版五文件移入相应项目目录的 `old/`。保存结果和必要目录信息足够确认时，不回读全文。
5. 若保存或归档部分失败，保留已有文件，记录实际完成项；恢复时只补缺失操作。每个完成的新版仍完整保存并归档，不降低保存频率。

候选通常留在工作区；尚未完成且难以重做的工作可以保存恢复检查点。已有名称冲突先核对真实状态，避免覆盖未知内容。完成保存后按用户授权范围继续或停止。

## 本地工作台命令

将技能目录记为 `MATH_DOC_SKILL_DIR`；以下命令只操作本地文件系统：

```bash
python3 "$MATH_DOC_SKILL_DIR/scripts/research-workbench.py" init-project <项目目录> --name <项目名> --goal <研究目标>
python3 "$MATH_DOC_SKILL_DIR/scripts/research-workbench.py" prepare-session <项目目录>
python3 "$MATH_DOC_SKILL_DIR/scripts/research-workbench.py" begin-revision <项目目录> --bump <patch|minor|major> --round-type <substantive|review|maintenance>
python3 "$MATH_DOC_SKILL_DIR/scripts/research-workbench.py" append-log <项目目录> --summary <本轮摘要> --unresolved <未决事项>
python3 "$MATH_DOC_SKILL_DIR/scripts/research-workbench.py" validate-project <项目目录> --candidate
python3 "$MATH_DOC_SKILL_DIR/scripts/research-workbench.py" finalize-revision <项目目录>
```

初始化可用 `--reference <参考材料>` 登记来源。研究回顾记录另加 `--review-outcome <continue|rewrite|return|stop>`。

`prepare-session` 逐字输出当前入口；JSON 格式把原文放在 `entry_text`，不加载全部数学正文，也不按旧字段转译。`begin-revision` 完整复制并更新候选元数据，已发布文件保持原样。`validate-project` 默认检查当前版本，`--candidate` 检查候选发布条件。结构检查与人工数学审阅分开；普通科研文字不由正则表达式判定含义。

`finalize-revision` 保留复制中断恢复、追加日志、完整发布和归档检查，只代表本地完成。文件冲突保留源文件；中断时核对实际位置后继续未完成操作。
