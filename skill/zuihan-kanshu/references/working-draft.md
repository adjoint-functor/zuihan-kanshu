# 数学文稿与独立控制文件

本约定适用于讲义、报告、问答整理、解释稿、审阅意见、翻译稿和成品稿。研究工作台仍使用 research-workbench.md 的五文件；从研究稿派生的读者文稿按本约定管理。

## 正文、控制与产物

普通文稿保持灵活，不套用研究五文件结构；按用户明确要求、既有有效约定、文稿类型和读者需要决定章节与输出范围。纯对话问答不要求文件；明确只要 Markdown 或仍在筹备时，按该范围交付。完整成品默认包括独立控制 Markdown、干净正文 Markdown 和同版 PDF，TeX 按用户需要交付。

| 文件 | 职责 |
|---|---|
| <文稿名>_vMAJOR.MINOR.PATCH.md | 唯一可编辑的完整读者正文源 |
| <文稿名>_vMAJOR.MINOR.PATCH.control.md | 当前工作的入口、来源、计划、偏好、构建和编辑记录 |
| <文稿名>_vMAJOR.MINOR.PATCH.pdf | 同版阅读成品 |
| <文稿名>_vMAJOR.MINOR.PATCH.tex | 按需交付、实际用于编译该 PDF 的派生 TeX |

TeX 所需图片、宏等资源按实际需要随对应版本交付，构建器生成的同名 .resources/ 目录与 TeX 一同发布和归档。正文可以按章节、卷册或语言分文件，但必须明确当前编辑来源与产物关系，避免多份同权正文。

正文保留标题、范围、必要先备知识、定义、命题、证明、例子、引用和参考文献。假设、条件性结论、反例、证明缺口和开放问题属于数学内容，不移出正文。计划、处理经过和构建信息进入控制稿；不把读者需要的定义、脚注、链接、标签或书目项藏在那里。

## 接收与整理实际输入

先结合实际文件、当前用途和有效约定，判断是否需要输入适配。材料已可直接使用时继续处理；若 Markdown 混有读者正文、工程配置和维护记录，模型自行按用途整理为正文、控制稿及必要资源，不要求用户预先手工转换，也不因格式不同而重建整份文稿。

保留原始来源，在完整副本上做必要分离并记录来源与实质调整。按内容判断去向，不仅凭章节名、注释标记或文件年龄删除；读者需要的算法、代码示例、数学限制、反例和证明缺口仍属正文。标题、作者、日期、语言等成品 metadata，以及正文需要的宏、标签、脚注、链接和书目依赖，要保留或迁入可用的资源位置，必要时更新引用路径。

已有正文、控制稿或构建入口时先辨清实际生效关系。能从材料确认的整理直接完成；若多个配置或正文互相冲突且无法判断，以具体差异询问，不靠版本号猜选、不覆盖来源。整理后的当前输入才交给构建器；脚本负责校验和构建，不代替模型解释任意输入格式。

## 控制文件

控制稿使用自然语言记录当前事实；以下五部分按实际内容填写，不要求为无关事项补表。接续时先读目标、当前计划和必要定位，再读取相关正文，可靠的本地副本可以复用。

1. **文稿目的与范围**：用途、读者、先备知识、来源基版、处理范围、当前阶段和完成尺度。
2. **近期计划**：待启动或正在执行的安排、事项的目的与依赖、完成尺度、必要材料及正文锚点、实际待决问题。已完成或被替代的任务及时移出当前安排；可以明确暂无后续任务。
3. **定制偏好与避坑**：用户已确认的文风、详略、术语和格式偏好，以及有依据的具体问题与适用范围。助手建议和随口用词不自动成为项目约定；术语采用仍按 chinese-translation.md 和内置表。不要把一次局部问题扩张成通用禁令。
4. **来源与构建**：实际使用的来源版本、当前正文与产物文件名、必要资源、构建配置。只生成正文或筹备计划时无需配置 PDF。需 PDF 时在这里放 final-pdf-build-profile.md 规定的唯一 build_profile 块；构建器只读该块，不将计划或全篇控制稿作为正文输入。
5. **编辑与检查记录**：日期、版本、实质变化与理由，实际完成的数学、语言和排版检查，以及仍存限制。以可恢复和可理解为准，不逐条记录工具调用、不复制正文或整段聊天。

计划和检查说明可更新并记明日期，仍指向同一成品版本；归档时保留当时的完整控制稿。只改这类记录不要求重编 PDF。正文、构建配置或实际依赖改变时，重新生成并检查相应产物；已交付正文的修改按下一版本候选进行。不要为记录一条最终检查事实重复构建未变产物。

## 讨论、制订计划与执行

允许先在数学问答中充分讨论，再把整理后的具体计划保存到控制文件，等待用户启动。计划应足以接续：说明目标、范围、当前认识、必要依赖、工作顺序和完成尺度；顺序不等于不可调整的逐轮配额。

用户要求“先制订并保存计划，暂不执行”时，完成授权的筹备，把当前安排明确写为待启动，仅交付计划和必要说明。保存计划不构成执行授权；不因此修改正文、运行计划中的实验或发布成品。已有正文时保持其版本，控制稿可以单独补充当前筹备记录。

收到“开始”“按计划执行”或上下文明确的继续指令后，按已授权目标连贯推进。主代理在当前会话授权和宿主规则允许的范围内，自行决定批次内的任务拆分、推进节奏、保存时机和实际需要的代理，不自行增加轮数、token 或费用预算，也不把每个保存节点设成人工批准关卡。用户明确的单轮、暂停或范围限制继续有效。

根据研究结果、文稿状态和依赖变化重排、合并或撤下当前事项，简要记录重要调整的理由。保持用户已确认的目标和限制；需要改变目标、结论强度或关键取舍时，再带具体问题和建议询问。已授权范围内的方法调整直接处理。某个证明缺口不自动成为下一步，达到完成尺度后可以收束。

轮次与批次沿用 SKILL.md 的约定：一个计划的批次可跨多个对话轮次，完成尺度不由轮数或文件版本数决定。批次内默认先完成约定范围的数学内容，再按需中文翻译、按需文风整理，最后按需编译 PDF；不要求等整个学科问题解决，也不因这一次序强制调用翻译或文风。数学部分以本批次的完成尺度和真实结果判断；保留未决问题并明确收束的阶段稿也可进入后续整理。数学进行中可以直接用中文记述和整理必要论证；除非用户要求阶段稿或另定顺序，不为每个中间结果启动一遍成品流水。

执行过程受宿主实际会话能力约束。需要暂停或发生中断时，把真实进展、尚缺内容和接续位置写入控制稿；后续据此继续，不把技能文字描述成后台自动运行能力。

## 修订与保存

输出目录按 `SKILL.md` 的“执行与保存”约定确定；具备 Work/Library 云端保存能力的新建文稿或写作计划，未指定目录或仅要求云端时，使用云端库根目录下按任务主题自动命名的新子目录。已有任务续作沿用原目录；其他宿主依据用户目的地与当前工作区能力保存。当前版本直接放在确定的输出目录，候选及构建中间物放同目录 tmp/，上一版放 old/。开始前核对实际当前目录；目录移动不升版。保持完整复制后局部编辑，不通过模型重新生成未变全文。结合当前目标理解实际材料，保留仍有效的数学内容、来源与历史记录。

正常修订增加 PATCH；结构或用途显著变化增加 MINOR；重新定义目标才增加 MAJOR。同组正文与产物的版本一致。翻译或文风衍生稿记录实际来源、版本和范围，不覆盖来源，也不把语言与排版变换记为数学进展。

已有文稿可使用本地工具安排同一版本的发布组。例如从有 Markdown、控制稿与 PDF 的当前版本开始：

```bash
python3 "$MATH_DOC_SKILL_DIR/scripts/versioned-output.py" begin-revision <输出目录> \
  --current finished_v1.0.0.md --current finished_v1.0.0.control.md \
  --regenerate finished_v1.0.0.pdf --next-version v1.0.1
```

--current 完整复制可编辑来源；--regenerate 为已有派生文件或资源目录登记新候选，不复制旧 PDF 占据生成路径。首次增加控制稿、TeX 或同版资源目录时，用 --add 指定新版本 basename；例如 --add finished_v1.0.1.tex。已有 TeX 与资源目录则随 PDF 一起 --regenerate。新文稿无上一版时，直接在 tmp/ 准备完整首版，核对后保存到输出目录。

候选齐全且完成必要检查后运行 finalize-revision <输出目录>。新版本目标与 old 归档有重名时先处理冲突，不覆盖。中断时用 inspect <输出目录> 核对阶段，再按相同参数继续 begin-revision 或重跑 finalize-revision；不要删除仍在使用的续作清单或部分候选。

这些脚本只操作本地文件。须按宿主实际可用的方式，将本次交付的控制稿、正文、PDF、按需 TeX 及必要资源保存到已确定的输出目录；具备 Work/Library 云端保存能力时，按 Library 技能实际保存到对应云端目录。本地完成不代表远端已保存。确认新版全部保存成功后，再把上一版完整成品组移入相应目录的 old/。局部保存失败时保留已保存文件与尚缺清单，补齐后继续，不提前归档旧组。Git 承担持久化的文稿按其仓库流程保存，不重复另存一套当前实现。

## 交付检查

根据实际变化检查正文完整性、数学条件和引用、文风与术语，以及版本和产物对应关系。明确只做文风、翻译或排版时，实质数学错误交回主代理，在已有数学修订授权内处理，或明确所需范围后处理；不暗中改强结论。

新论证、核验反馈与依赖变化按 mathematical-judgment.md 判断，委派按 document-roles.md；只检查当前变化及受影响部分。PDF 按 final-output.md 完成实际编译、机械预检和视觉检查。确认真实保存和归档结果后简要交付。计划尚待启动或问题尚未解决时，准确说明当前状态，不把结构检查当成数学证明。
