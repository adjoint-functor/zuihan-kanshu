# 文献阅读、使用与下载

导航：[共同边界](#共同边界) · [及时检索](#及时检索与已有成果) · [三种能力](#三种互补的检索能力) · [筛选与采用](#查询筛选与采用) · [文献状态](#文献的两个轴) · [下载命名](#网络下载文献与文件名规范)

按当前问题选择材料和阅读范围，记录实际使用的版本、结论与适用条件。普通问答和文稿工作可以直接使用；持续研究的条目保存在参考资料台账。

## 共同边界

- 参考材料持续提供问题、方向、记号、证明路线、计算策略、反例和文献线索；
- 从未经核验的研究稿或笔记实际采用的数学主张先按待验证处理；仍有效的既有核验可以直接复用。问题、动机、反例候选和思路可直接帮助探索；
- 数学状态按实际检查改变；成熟文献作为工具通常核对准确陈述与适用性，不默认重证文献全部内容；
- 按当前用途读取自然章节或相关证明及依赖，不因引用一个结果启动整份来源的重审；持续研究接纳的内容统一进入当前数学主稿；
- 用户已经给出清楚目标时直接开始，只有范围存在实质歧义才询问。

## 及时检索与已有成果

把文献判断接入实际数学决策，不只在不会证明或工具失败时才检索。提出新的研究方向或实质子问题、准备投入较大工作重建理论、判断候选的新颖性时，先核对已有成果；重要改道、新术语或跨领域机制出现时，重新判断检索需要。已有资料足以支持当前判断时直接复用。基础问答、常规练习和明确要求的自足证明不必机械搜索；能够自行证明不构成结果新颖的证据。

查询要表达实际对象、假设和结论，可换用等价表述、别名及起作用的机制，必要时沿原文参考文献和后续引用扩展。不能只搜自拟标题或一个术语。发现已有结果后比较假设、强度、方法和用途，再决定引用、改道或研究新的证明、推广及应用；重复已有结论不使全部工作失去价值。

成功无命中不表示文献不存在，更不证明新颖。结合语种、年代、收录范围、表述与筛选条件判断遗漏；若据检索作出研究取舍或新颖性判断，简明保留实际查过的范围和未覆盖处。访问失败与成功无命中分开报告。不设置固定搜索轮数、论文数或新的长期核查表。

## 三种互补的检索能力

三种能力均可服务普通问答、持续研究与文稿，由数学责任人按问题选择、组合和调整，不要求固定先后或每次全用。

| 能力 | 主要用途 | 使用入口 |
|---|---|---|
| 原生 Web、论文和书籍检索 | 最新论文、综述、原文、书目信息、发表版本与引用链 | 当前环境的原生检索与阅读工具 |
| Matlas | 按数学陈述、假设或机制寻找书籍及论文中的候选结果 | matlas.md |
| TheoremSearch / TheoremGraph | 检索数学陈述；按需查看 arXiv 非形式化陈述之间抽取的引用和依赖线索 | theorem-search.md |

已知作品时可直接读原文。各服务的覆盖不同，不能把单个语义索引视为全部数学文献；检索能力不可用时使用可访问的其他入口，并保留实质影响判断的覆盖限制。

## 查询、筛选与采用

只外发公开内容或可抽象成通用数学问题的查询；使用未公开主稿、私有项目全文或未公开推导须符合用户明确授权的范围。查询不自动附带项目文件。

按问题调整返回量、过滤条件和查询表述。客户端默认较多候选、分段预览元数据；预览条数不是选读上限，结果条数也不是独立文献数。继续查看仍有价值的候选，相关性差时先改写查询或放宽不当过滤，覆盖不足时换来源。主代理或当前探索者自主判断，无需逐次批准参数。

候选命中、相似度、自动摘要和图边都是定位线索。采用前回到来源的准确陈述、假设、版本与当前适用性；借用方法时阅读相应证明及必要依赖。抽取的正文或 proof 字段也可能缺失上下文、错配位置，不能当作原文核验已经完成。

普通问答直接引用实际采用的来源，普通文稿把必要工作记录写入控制稿，持续研究使用既有参考资料台账。只记录有用的来源、原文定位、版本、用途与核对状态；完整搜索结果按需暂存 tmp/，不为一次检索增加长期文件。

## 文献的两个轴

### 公开身份

- `已发表`：可以从期刊、会议录、DOI 或正式出版记录确认；
- `已出版`：可以从出版社、正式书目或图书馆目录确认；
- `仅预印本`：公开可得，但未查到正式发表或出版；
- `身份待核`：题名、作者或版本尚不能可靠对应。

公开身份与数学使用分别记录。预印本可以提供方向，也可以有已完成的数学核验；发表状态变化不重置已有核验事实。正式发表也不保证每个命题或当前用法正确，具体证据与依赖按 mathematical-judgment.md 判断。

### 本项目数学使用

- `待验证`
- `陈述已核`
- `适用性已核`
- `独立重建`
- `修正后可用`
- `不适用`
- `发现错误`

使用成熟文献作为工具时，通常核对准确陈述、版本、勘误和本项目假设即可；若当前任务要求核对证明、适用性复杂或出现错误迹象，则完整重建相关论证。局部笔误不撤销作品的公开身份。

这些词用于简明描述已做的工作，不是逐级解锁的流程。说明实际使用的结论、定位、必要条件及尚缺证据；普通问答可以直接在回答中交代，持续研究写入现有台账。

## 网络下载文献与文件名规范

以下条款均为规范性定义；示例不得补充、改变或替代这些条款。

### 规范地位与适用范围

- 只有用户资料库缺失所需文献，或当前项目必须取得另一版本时，才把网络文献保存到项目 `download/`；不得把资料库已有文件机械复制进项目。
- `KEY` 共享 BibTeX `alpha.bst` 与 BibLaTeX `alphabetic` 的 alpha-style 姓名缩写、年份和消歧原则。下文的精确人数算法是本项目规范，具体采用传统 BibTeX `alpha.bst` 的分段，并与 JabRef `authorsAlpha` 的人数分段一致；它不声称等同于可配置的 BibLaTeX `alphabetic` 默认值。可核对 [BibTeX 标准样式及其文档](https://ctan.org/tex-archive/biblio/bibtex/base)、[BibLaTeX 手册](https://mirrors.ctan.org/macros/latex/contrib/biblatex/doc/biblatex.pdf) 和 [JabRef citation key patterns](https://docs.jabref.org/setup/citationkeypatterns)。
- 完整可读文件名是本项目的存储约定，不是出版社、国家或国际组织制定的统一文件名标准。[JabRef file links](https://docs.jabref.org/finding-sorting-and-cleaning-entries/filelinks) 只作为关联文件管理的实现参考；不得把软件示例当成命名规则本身。

### 文件名语法

```text
FILE_NAME := "[" + KEY + "] " + TITLE + " — " + CREATOR
             + OPTIONAL_VERSION + "." + EXT
OPTIONAL_VERSION := "" | " — " + VERSION
KEY := AUTHOR_YEAR_KEY | SERIES_KEY
AUTHOR_YEAR_KEY := STEM + YY + DISAMBIG
SERIES_KEY := SERIES + VOLUME
VERSION := ARXIV_VERSION | REPOSITORY_VERSION | OFFICIAL_EDITION
```

方括号、右方括号后的一个空格，以及分隔符两侧各一个空格均为字面字符；分隔符是 U+2014 EM DASH。`DISAMBIG` 允许为空。`VERSION` 只有在下文规定了可核的来源标识、版本标识或版次时才出现，否则 `OPTIONAL_VERSION` 必须为空。

### 权威元数据与责任者

1. 题名、责任者、年份、版本和文件类型必须来自与当前文件相对应的权威元数据记录，不得拼接不同版本的字段。
2. 正式发表或出版的文件依次核对出版者或期刊的正式记录、DOI 注册记录和作品自身题名页；仅预印本核对其官方预印本记录和文件首页。存在冲突时先解决冲突，不能确认时停止命名并标为待核。
3. `CREATOR` 和 `STEM` 使用同一责任者列表：优先使用作者；无作者的书籍或会议录使用编辑者；两者均无而作品明确以机构署名时使用机构。责任者仍不能确定时不得自造主题键。
4. 人名保持权威元数据中的显示形式和顺序，`CREATOR` 中以逗号加一个空格连接。单名编辑者作为回退时在列表末添加字面后缀 ` (ed.)`，多名编辑者添加 ` (eds.)`；机构责任者使用其正式名称。
5. `STEM` 只使用权威元数据给出的拉丁字母姓名形式。非拉丁姓名必须使用出版者、作者身份记录或官方预印本记录提供的罗马字形式；没有可核形式时停止命名，不自行音译。自然人姓名还必须能从结构化元数据确定姓名前缀和姓氏；仅有显示字符串且不能无歧义拆分时同样停止命名。

### `KEY` 的确定算法

先把每名自然人责任者的姓名前缀和姓氏拆成有序词元。每个词元执行 Unicode NFKD 规范化并删除组合附加符号；若结果仍含基本 ASCII 拉丁字母以外的字母，必须改用权威元数据提供的 ASCII 转写，缺少该转写时停止命名。随后删除标点和空格。单词元三字母缩写采用首字母大写、其余字母小写；多词元或多责任者的各词元首字母一律大写。令 `N` 为责任者人数，令每名责任者的姓氏缩写为其姓名前缀及姓氏各词元首字母的顺序连接：

- `N = 1`：单词元姓氏取前三个字母，不足三字母时全部取用；多词元姓氏取各词元首字母。
- `2 ≤ N ≤ 4`：按责任者顺序连接全部责任者的姓氏缩写。
- `N ≥ 5`：按责任者顺序连接前三名责任者的姓氏缩写，并在末尾添加 `+`。
- 机构责任者优先使用权威元数据中的正式稳定缩写并保持其官方大小写；没有正式缩写时，移除名称开头的冠词，再按单词元规则取规范化机构名称的前三个字母。

`YY` 是四位书目年份的末两位。首次命名时已有正式发表或出版版本的，采用该正式版本年份；当时只有预印本的，采用首个公开预印本版本的年份。`KEY` 一经台账记录或正文引用便保持不变，后续预印本更新或正式发表不得改写它。

以 `STEM + YY` 检查当前项目台账和 `download/`、`old/download/` 中的碰撞：

- 基键未占用时，`DISAMBIG` 为空。
- 同批首次登记的碰撞项依次按规范化原文题名、规范化责任者和稳定来源标识排序；前两项均执行 Unicode NFC、大小写折叠和空白压缩。缺少稳定来源标识且三项仍不能区分时，停止并先判定是否为重复记录。排序后依次使用小写拉丁后缀序列 `a` 至 `z`、`aa` 至 `az`、`ba` 至 `bz`，再按同一双射二十六进制字母序列继续，直至足以唯一标识。
- 已登记键不得重新编号；以后出现的碰撞项使用上述序列中尚未占用的最小后缀。
- 碰撞检查采用 Unicode 大小写折叠，不得借大小写制造两个键。

首次命名时，当且仅当文件属于出版者定义的正式丛书、权威元数据同时给出正式稳定系列缩写和卷号，且组合键在项目中能唯一识别该系列卷时，必须使用 `SERIES_KEY`。`SERIES` 保持正式缩写的官方大小写；`VOLUME` 保持卷号的官方字母数字次序。两者都执行与 `STEM` 相同的 ASCII 转写停止规则，并只保留 ASCII 字母和数字；任一结果为空、不能安全转写或组合键碰撞时，必须使用 `AUTHOR_YEAR_KEY`。不得在两类键之间任选，也不得新造主题式临时键。已在台账或正文使用的稳定 `KEY` 优先于这项首次命名规则，不因后来进入正式丛书而改变。

### 题名、版本与文件系统规范化

- `TITLE` 使用权威元数据中的原文题名，保留原有语言、词序、大小写和变音符号；先做 Unicode NFC 规范化，再把连续空白压缩为一个空格。
- `CREATOR` 保留权威元数据中的姓名拼写和顺序；它与 `STEM` 的基本拉丁字母规范化相互独立。
- 对 `TITLE`、`CREATOR` 和 `VERSION`，冒号替换为带单空格的 EM DASH，正斜线和反斜线替换为连字符，删除 `< > " | ? *`、控制字符以及字段末尾的空格或句点；随后再次压缩连续空白。不得删除 `KEY` 外的变音符号。
- `EXT` 必须与实际文件格式一致，并规范为不带前导点的小写扩展名。
- 整个文件名按 UTF-8 计不得超过 240 字节。超限时，把 `TITLE` 替换为“可容纳的最长非空原题名前缀 + `…`”：有空格分词的语言只能在词边界截断，其他语言在 Unicode 字素边界截断。若连一个题名字素和省略号都不能容纳：责任者不少于四名时，先把 `CREATOR` 确定地缩为前三名加 `, et al.`，再从完整题名重做最长前缀计算；责任者少于四名时直接停止命名。缩写责任者后仍不能满足上限时也停止命名。不得截断 `KEY`、`VERSION` 或 `EXT`。
- arXiv 文件的 `ARXIV_VERSION` 必须为 `arXiv-<ID>v<N>`，其中 `<ID>` 和 `<N>` 取自当前下载文件的官方版本标识；标识中的斜线按上述规则替换为连字符。
- 其他预印本仓储有稳定记录标识时，`REPOSITORY_VERSION` 必须由仓储官方短名、记录标识和存在时的官方修订标识依次以连字符连接；所有字段均来自当前文件的官方记录并执行上述禁用字符替换。没有稳定记录标识的非 arXiv 预印本令 `OPTIONAL_VERSION` 为空，并在台账记录精确来源 URL 和取得时间，不得伪造 arXiv 标识或版本号。
- 正式发表或出版文件仅在出版者明确区分版次或修订号时，才以该官方字面标识构成 `OFFICIAL_EDITION`；不得自行发明书目版本标签。

### 更新、迁移与台账

- 更新版本不得静默覆盖。新取得的文件先以最终规范名暂存到 `tmp/download-incoming/`，完成文件格式和元数据核对后才发布到 `download/`。
- 若 `download/` 中没有同名文件，把暂存文件原子移动到该目录。若已有同名旧文件，先把旧文件移动到 `old/download/`，再原子发布新文件；发布失败时必须把旧文件恢复到 `download/`。
- 同名旧文件的归档名在扩展名前插入 ` — superseded-<UTCSTAMP>`，其中 `UTCSTAMP` 固定为移动时的 UTC `YYYYMMDDThhmmssZ`。归档名碰撞时，在时间戳后添加连字符和上述最小未用小写字母后缀。该后缀只标识本地归档事件，不冒充出版者版本。
- 规范名不同的被替代旧下载保持原名移入 `old/download/`；若归档目标已存在，则同样插入 `superseded-<UTCSTAMP>` 并按上述碰撞规则选择后缀，绝不覆盖已有归档。移动后不得在两个位置留下同名的双份当前文件。
- 台账必须记录精确本地文件名、来源标识、取得时间、实际使用版本和当前公开身份。预印本正式发表后补充正式出版信息，但保持已使用的 `KEY` 不变。
- 文件名、公开身份与可下载性均不自动授予具体数学命题的适用性；数学使用仍按双轴状态单独核验。
