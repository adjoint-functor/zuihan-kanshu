## 职责与单一正文源

数学产物结构、独立控制文件、版本、写作与审查顺序由 `working-draft.md` 规定；本模组负责成品排版、构建和检查。默认在全部适用审查完成后的最终成品轮按交付目标制作 PDF；主体、整体修订、导语及语言审查等中间轮只保存正文、控制与必要资源。用户明确要求阶段 PDF 可以覆盖时机；只做问答、计划或 Markdown 时不自动编译 PDF。

成品 Markdown 是唯一可编辑的文档正文源，保持完整、干净。独立控制稿记录来源、配置、计划与检查；PDF 以及按需交付的 TeX 从同一正文和配置派生。实际用于编译该 PDF 的 TeX 可与同版必要资源一起交付，临时 reader、日志、渲染页和检查报告仍放 `tmp/`。

下一版从最新成品 Markdown 继续，不从旧 PDF 或生成过的 LaTeX 恢复内容。旧 PDF 可用于视觉回归。只在临时 reader、TeX 或 PDF 上完成的修补应回写正文、配置或资源，再生成对应产物。

研究项目的读者衍生稿使用明确版本的数学主稿并记录来源；它不成为下一轮研究入口，语言与排版修改不反写研究主稿。

## 正文与控制配置

接收材料时按 `working-draft.md` 判断是否需要整理混合输入，保留数学内容与依赖。构建前确定当前正文，以及独立控制稿中的唯一 `BUILD_PROFILE` 块；字段、资源声明、文件名限制和工具链要求见 `final-pdf-build-profile.md`。当前构建器接受单个正文 Markdown 与独立控制稿，分章正文需先确定本次完整构建入口。

## 候选检查与构建

从输出目录根检查候选正文、控制配置、资源、字体和公式：

```bash
python3 "$MATH_DOC_SKILL_DIR/scripts/final-pdf-build.py" inspect \
  tmp/finished_v1.0.1.md --control tmp/finished_v1.0.1.control.md \
  --json-report tmp/final-source-inspection-v1.0.1.json
```

需要检查客观描述性标题时可以加 `--third-party-headings`。检查器只报告可疑标题和可能应行内化的公式，由编辑者结合文种与数学语义判断，不自动改写。

用同一输入生成 reader、实际编译用 TeX 与 PDF：

```bash
python3 "$MATH_DOC_SKILL_DIR/scripts/final-pdf-build.py" build \
  tmp/finished_v1.0.1.md --control tmp/finished_v1.0.1.control.md \
  --reader tmp/finished_v1.0.1.reader.md \
  --pdf tmp/finished_v1.0.1.pdf \
  --build-log tmp/finished_v1.0.1.log \
  --json-report tmp/final-build-v1.0.1.json
```

需要交付 TeX 时在同一次构建追加 `--tex tmp/finished_v1.0.1.tex`，与实际需要的同名 `.resources/` 一起交付和归档。构建失败时保留诊断材料，解决问题后使用新的输出路径，不把失败候选发布为当前版本。

## 公式与字体

数学表达式默认随文排入。只有需要编号或回引、包含多步推导或对齐、结构在行内明显破坏可读性、无法适应最终版心，或属于确需独立辨认的核心恒等式时使用陈列公式。

短小、无编号、无需回引且只作为句法成分的表达式保持行内。陈列和编号分别决定；陈列公式仍保留句法标点。长式只在关系符、加减号等语义边界断行并对齐，不拆分分式、矩阵、分段结构或成对定界符。是否超宽由最终字体、版心、构建日志和渲染判断，不按源码字符数判断。

字体的配置与空心字体契约见 `final-pdf-build-profile.md`。核对实际可用字体和最终字形，不把源码中的代码示例当作数学排版。不得通过全局缩小字号、压缩页边距或普遍禁止跨页来掩盖溢出和分页问题。长证明、定理和表格应在合理位置自然跨页。

## 机械预检与视觉检查

对实际候选 PDF 和对应构建日志运行：

```bash
python3 "$MATH_DOC_SKILL_DIR/scripts/preflight-pdf.py" \
  tmp/finished_v1.0.1.pdf \
  --build-log tmp/finished_v1.0.1.log \
  --render-dir tmp/rendered-v1.0.1 \
  --expected-version v1.0.1 \
  --json-report tmp/pdf-preflight-v1.0.1.json
```

若来源检查报告显示使用了大写 `\mathbb`，同一命令追加 `--require-font MSBM10`。预检检查构建警告、元数据、字体嵌入、Type 3 字体、文本提取、页边界溢出、书签与内部链接目标、附件、控制配置残留、稀疏页面及全页渲染。每次使用新的、尚不存在的渲染目录和报告路径，避免旧图混入。

预检记录最终编译轮次的 LaTeX／Package／Class 警告及其消息，包含 xeCJK 字体族警告；早期轮次已经解决的引用警告不重复计入。返回码为零仍可能有 WARN，须查看报告并处理或说明实际影响，不能把零返回码写成零警告。

预检成功不等于视觉通过。必须：

1. 查看覆盖全部页面的 contact sheet；
2. 高分辨率查看所有警告页和本轮变动页；
3. 抽查积分、求和与乘积、根式、多层上下标、定界符、对齐公式、矩阵、表格、长定理或证明、引用和最后一页；
4. 检查中文公式字形、AMS 空心大写轮廓、裁切、重叠、重复公式、横向溢出、断链、意外空白页和无法解释的稀疏页；
5. 检查提取文本、元数据和书签中没有控制配置标记或用户另行指定的内部模式；普通嵌入附件不得混入成品。标准 C2PA 内容凭证按关系、嵌入流 MIME 与 JUMBF 容器结构单列记录，不算普通附件；这不表示已验证签名、资产绑定或信任。保存服务可能添加凭证，核对实际交付副本的分类结果。

只有实际打开渲染页后才能声称完成视觉检查。

## 检查记录与发布

对实际准备交付的正文、配置、资源和产物完成检查。正文、构建配置或实际依赖变化后，在下一次交付相应 PDF 时重新生成并检查受影响产物，不要求每个中间轮编译。排版若改动结论、条件、记号或结构，按 `working-draft.md` 回查受影响的一致性及导语。只在控制稿补充计划、编辑说明或真实检查结果，不要求重编未变 PDF。

把实际输入、构建命令与环境、结果、视觉检查范围和未决问题记入控制稿，可引用 `tmp/` 中的详细报告。记录必须与实际发生的检查一致；不为写入最后一条检查事实重复冻结、生成和检查同一内容。

按 `working-draft.md` 的保存和归档流程交付已检查的候选。最终新版控制稿、正文、PDF、按需 TeX 与必要资源全部保存成功后，再归档被替代的旧成品组；中间轮只以本轮实际交付范围判断保存是否齐全。日志、reader、渲染页与详细报告留在 `tmp/`。

交付实际请求的文件，说明有意义的检查结果与仍存限制。不得把编译成功说成视觉通过，也不得把排版检查说成数学证明。
