# 更有效地使用瑞般观珠

瑞般观珠可以回答数学问题、接续数学研究，也可以规划和制作数学文稿。把你想得到什么、已经有什么、希望这次做到哪一步说清楚，通常比给出一长串操作步骤更有效。

首次使用时，在输入框输入 `@` 并选中实际的**瑞般观珠**插件。下面提示词中的 `@瑞般观珠` 都指这个选择；选好后可以直接用自然语言继续交流。

## 使用环境、模型与语言

请在 **ChatGPT Work** 中使用，在云端启动、查看和接续数学工作，无需自行准备远程主机或维护服务器。工作间隙、出差途中和旅行路上，都可以接着做数学；与 Codex 的适配尚未检验。

预算充足时，主智能体建议选择 **GPT-6 Astra／Max**，最低建议 **GPT-6.1 Sol／Max**。你当前选择的主智能体负责统筹、关键数学判断和最终整合。插件已经写好子智能体分配方案，尤其是数学研究中的探索、证明与核验分工；通常使用 Max 即可，**默认不建议 Ultra**。具体能使用哪些角色和模型，取决于当前环境提供的能力。

初步粗测中，GPT-6 Astra 与 GPT-6.1 Sol 的消耗占比约为 **4∶1**；按约 5 倍单位消耗作简化折算，等价用量约为 **4∶5**，Sol 占一半以上。这是粗测参考，实际分工随任务而变。

已有用户实测，**中文、英文和日语均可正确运行**。你可以用习惯的语言提问，也可以要求插件用指定语言解释本指南。

中文指导也用于日常中文问答、规划和研究简报，从组织表达时处理术语、自然中文和数学条件。输出语言以你的明确要求为准，结合当前交流及可靠上下文判断；仅仅引用中文材料或提到中日文名称，不会强制改用中文。

## 随时询问怎么用

不必记住全部功能，直接问：

```text
@瑞般观珠，告诉我怎么用得更有效率。
```

也可以加上你的场景，例如“我准备开展数学研究”“我想把已有证明整理成文章”。插件会结合本指南说明适合的用法。

## 数学问答：直接说出当前疑问

直接提问即可，也可以说明想要直觉、简短证明或完整推导，以及相关的已有基础。数学回答从组织时就采用文风指导，优先按你这次的要求，再结合已可靠说明的相关背景决定详略与先备；不会把某个领域的专长当作熟悉所有领域。信息足以回答时直接开始，不先做背景问卷。

基础问题简洁充分，复杂问题可以完整展开，必要条件和承重步骤都会保留。普通问答、数学讨论与暂停后的追问默认在对话内完成，能自然承接相关上文，不自动创建研究五文件、稿件控制或术语附录、审查轮次或 PDF。你明确要求文件、文稿或正式研究时，再按对应范围处理；下文的共享中文参考按独立约定维护。

## 数学科研开题：材料充分可直接开始

开题时建议上传 **Markdown（.md）或 PDF** 说明文件，集中写清研究目标、背景、已知结果、参考线索、重要限制和期待的成果。有现成草稿、证明或资料时一并提供，不必先改成固定模板。材料充分且已要求开始时，可以直接开展研究，不强制先审批研究计划。

```text
@瑞般观珠，请阅读我提供的说明材料，依照插件规范开始研究，并保存研究记录与阶段成果。
```

只有大方向、希望共同梳理目标时，可以选择先讨论：

```text
@瑞般观珠，我想研究……。请先和我讨论目标、已有基础与可行路线，暂不启动研究轮次。
```

已有研究继续沿用当前项目和保存位置；你也可以直接说明要接续哪个项目。

## 看完简报，再继续下一轮研究

研究轮次完成后，对话中会有简报，说明主要进展、关键思路、结果的作用以及接下来的安排或阶段状态。完整论证和可接续记录保留在项目文件中。

研究内部推导、检索和核验不受中文润色规则干预；每轮收束真正撰写给你的报告时，才使用适用的中文与文风指导。研究简报保留既有长度、结构和详略，文风指导改善清楚、准确与自然，不自行压缩扩写，也不套用问答的自适应长度规则。

如果对简报满意，可以直接说：

```text
依照 @瑞般观珠 的规范，按照你的判断，继续下一轮研究。
```

插件会结合总目标、可靠结果和阶段完成尺度判断下一步，可能深化当前路线、转向更有价值的方向，或建议收束。你也可以在这句话后补充本轮重点。

## 暂停轮次，追问细节或研判方向

想先理解研究细节时，可以说：

```text
暂停研究轮次，依照 @瑞般观珠 的规范，先回答我：请解释当前结果的关键想法、证明中最重要的一步，以及仍未解决的问题。
```

想重新判断方向时，可以说：

```text
暂停研究轮次，依照 @瑞般观珠 的规范，先回答我：请结合总目标和现有证据，研判当前方向是否值得继续，有哪些可信的替代路线，并说明你的建议。
```

也可以请它判断是否已经适合形成阶段成果：

```text
暂停研究轮次，依照 @瑞般观珠 的规范，先回答我：目前是否已有可以独立陈述的阶段性成果，是否适合收束成文？请说明可写成什么、依赖哪些已证结果，以及还缺什么。
```

这些问法会先转入你指定的讨论。为回答问题，可以读取相关材料、核对论证或作必要推导；讨论本身不会自动接着启动新研究轮次、改写正式结论或开始写稿。讨论后，直接说明继续研究或开始写作即可。

## 数学写作：把完整需求说清楚即可

写作前尽量一次说清读者、用途、主题与范围、现有材料、篇幅和深度、语言、格式，以及哪些数学内容允许修改：

```text
@瑞般观珠，我想写一份……，面向……，已有材料是……，内容范围、篇幅、语言与格式要求如下：……。
```

新写作批次默认先参考文风指导，中文稿也使用中文写作与翻译模组，制定计划并保存独立控制文件，再在对话中商量后停下。控制和简报会说明文章主线、核心与支线边界，以及拟定轮次如何推进它；无需另外加“先定计划、先不执行”的口令。

计划讨论清楚后，启动执行：

```text
依照 @瑞般观珠 的规范，开始执行已讨论的写作计划。
```

接续同一批次：

```text
依照 @瑞般观珠 的规范，继续下一轮写作。
```

一个计划及其实施构成一批次；一次你发起、助手回应完成的 Work 对话往返为一轮次，工具调用和子智能体返回不另算轮，也不要求新建 Work。已启动的批次继续执行，不每轮重新规划或索取同一批准。

主体按工作量、难度、依赖和篇幅灵活分轮，不固定一章一轮。主体完成后，当前实际主智能体亲自通读全稿并修改结构与数学表达的一致性，再定稿适用的论文式导语；这两项默认各一轮，短稿可按顺序合轮，不需要导语时跳过。研究论文、综述和独立数学论说默认有论文式导语；讲义、教材、演讲稿和题解通常采用适合体裁的引导，不另套论文式导语。

实质写作完成后，中文稿先完整审查术语与表达，再审查文风；长稿两项各一轮，短稿可在同轮依次认真完成。文风和中文指导从开始生效，后期审查仍须完成。后续改动涉及结论、条件、记号或结构时，按影响回查相关内容。

中间轮默认保存正文、控制和必要资源，不编译 PDF；全部适用审查完成后，最终成品轮按交付目标制作 PDF，只要 Markdown 则无需 PDF。你可以明确要求一次成稿或阶段 PDF：一次成稿可覆盖等待与分轮，仍会先使用适用指导并依序完成写作和检查；泛称最终要 PDF 不自动跳过规划。仅修某处、仅翻译或排版按指定范围处理，不扩成全稿写作。

## 保存位置

研究记录、写作计划与文稿默认保存在云端的库中。你可以直接指定库内目录，例如“请保存在库中的‘数学写作/某主题’目录”。未指定时，在 Library 根目录的 `瑞般观珠/` 下建立项目子目录：优先用你明确的项目名称，否则自主按主题命名，重名加简短区分，不为命名反复询问。首次默认保存会告诉你实际目录，后续无需每轮重复；接续已有项目沿用原目录，不自动迁移。

普通数学问答与使用帮助默认在对话内完成，不把每次回答保存成稿件或研究项目。没有云端保存能力的宿主按实际可用位置保存并说明限制，不把本地文件称作云端已保存。

## 全项目共享的中文参考

中文模组实际适用时，会读取库中 `瑞般观珠/zuihan-kanshu-Chinese.md`，全项目共用；确证不存在才初始化，读写失败不会当作不存在。它与项目子目录并列，普通稿件的保存位置不迁移它；你可以明确另选共享文件或位置。

其中只保存内置表未覆盖而已查证落实的新译名，以及你明确采用的个性化或例外规则，保留义项、依据和实际适用范围。随口用词不构成授权，局部选择不自动变成全局规则；普通补充也不覆盖内置精确表项。没有合格增量就不重写。共享参考的读取、必要初始化和增量保存独立于普通对话不建稿件的默认，也不替代文章末尾适用的术语表。细则见 [共享中文参考](shared-chinese-reference.md)。
