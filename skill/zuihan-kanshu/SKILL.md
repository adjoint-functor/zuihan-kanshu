# 瑞般观珠 v8.6.0

数学工作分为数学问答与解题、持续数学研究、数学文稿三条路径。按用户当前目标选择；日常推导、计算和核验可在问答中完成，持续研究使用研究工作台。用户明确指示优先于技能的默认建议。

## 按需选择路径

| 当前工作 | 首先读取 |
|---|---|
| 询问本插件的用法、使用指南或效率建议 | `references/usage-guide.md`；按用户语言在对话中回答 |
| 数学询问、解题或文献关系 | `references/mathematical-inquiry.md`；默认在对话中完成 |
| 持续数学研究 | `references/research-workbench.md`；探索与角色安排见 `references/research-roles.md` |
| 普通写作、整理、批改、写作计划或排版 | `references/working-draft.md`；普通文稿保持灵活 |

## 使用帮助与主代理

用户询问“告诉我怎么用得更有效率”“怎么用更高效”“使用指南”、"How can I use this plugin more effectively?"、"usage guide"、「このプラグインをもっと効率よく使うには？」「使い方を教えて」或相近意思时，按需读取 `references/usage-guide.md`，用用户当前使用或指定的语言解释。泛问时在对话中给出指南主要内容及可复制提示词，不只返回链接或能力介绍；已指定场景时围绕该场景组织，依请求可展开完整指南。

单独的使用帮助请求不启动研究项目、研究轮次或文稿制作。同一消息另有明确任务请求时，结合完整意图分别处理，遵守用户的执行、规划或暂停要求，不因帮助关键词丢失其他指令。暂停研究后仍可为回答所问作必要阅读、核对和推导；讨论本身不自动重开研究轮次、改写正式结论或开始成文。

由当前实际主代理负责统筹、关键数学判断与最终整合。预算充足推荐 `gpt-6-astra`／`max`，最低建议 `gpt-6.1-sol`／`max`；不强制切换当前主代理。插件已内置子智能体分工，数学研究另有探索、证明与核验安排，通常使用 Max 即可，默认不建议 Ultra。角色及层级仍按对应模组、宿主能力和当前授权采用。

## 按需补充模组

按实际工作补充以下模组：

- 数学问答与普通文稿需要实质执行或委派时，先读 `references/document-roles.md`；正式持续研究的执行分配使用 `references/research-roles.md`。
- 新论证、核验意见或依赖变化：`references/mathematical-judgment.md`。
- 新研究方向、准备投入较大证明工作、判断新颖性或使用文献时，读 `references/literature.md` 的相关部分，及时核对已有成果。原生检索、`references/matlas.md` 与 `references/theorem-search.md` 三种能力按需互补，普通问答也可使用；下载命名仍见文献模组。
- 数学问答、数学讨论、研究简报，以及数学文稿的新写、修订和一次成稿：组织回答或开始写作前加载并使用 `references/writing-style.md` 的通用语言表达与写作指导。问答详略与先备按其共享指导判断；研究轮次报告沿用既有简报安排，文稿规划和后期审读仍按 `references/working-draft.md`。
- 任何任务有实际预期的中文输出，包括帮助、规划、问答、研究简报和文稿，组织该部分前加载并使用 `references/chinese-translation.md`。从用户明确的输出语言、当前交流语言和可靠有效上下文判断；明确要求其他语言时服从该要求，模组说明、引文或来源中的中文及中日文名称本身不等于要用中文回答。没有中文输出意图时不强制加载或追问语言；混合／双语输出只对中文部分采用中文指导。
- 正式研究的内部推导、检索和核验阶段不加载中文模组；每轮收束真正撰写给用户的中文报告时才加载使用。若本轮已经加载，不据中文润色规则干预内部研究判断或过程，在报告阶段采用；不声称能卸载已读规则。明确另做翻译稿时按该翻译任务处理，不改变内部研究流程。
- 中文模组适用时，同时读取 `references/shared-chinese-reference.md`，按其约定使用全项目共享的个人中文参考，记录已查证补充及用户明确采用的翻译习惯、用词和保留词规则，并尊重实际作用域；它的读取、缺失初始化和合格增量独立于稿件管理。
- 需要英文术语的准确中译时读 `references/translation-glossary-en-zh.md`；涉及具体日本实体或相应人名术语时读 `references/japanese-names-places-zh.md`。两表按义项使用；临时对话用词不自动覆盖内置表。
- 全稿结构与数学表达的一致性审查：`references/structure-consistency-review.md`；适用的论文式导语：`references/introduction-writing.md`，由普通文稿流程衔接。
- 完整成品或 PDF：`references/final-output.md`；生成或重建 PDF、交付 TeX 时再读 `references/final-pdf-build-profile.md`。
- Work 云端环境重置、缺少 PDF 工具或字体时：`references/pdf-environment.md`，先检测复用，再按需恢复并以样稿验收。

已加载且仍适用的规则不重复加载，不为简单任务读取无关参考。中文和文风的生成指导适用于当前输出，不因加载就要求稿件控制、稿件术语附录、全稿审读、独立轮次或 PDF；共享中文参考按上述独立约定处理。跨路径任务按实际授权处理数学内容；仅作语言或成品变换时不得暗中改变数学状态。

一次用户发起、助手回应完成的 Work 对话往返称为“轮次”（其他宿主按相同口径）；整段线程、工具调用、子代理返回和保存节点不另计轮次，也不因分轮新建 Work。一个既定写作计划及其实施构成一批次；不按轮数决定是否完成。数学文稿的默认流程见 `references/working-draft.md`，持续研究仍按研究工作台及用户授权推进。

## 执行与保存

新建研究项目、文稿或其他需要保存的新任务时，采用用户指定的保存目录。若宿主具备 Work/Library 云端保存能力，未指定目录或仅要求“保存在云端”时，在云端 Library 根目录的 `瑞般观珠/` 下建立项目子目录：用户明确给出的项目名称优先，否则按主题自主拟定简洁、可辨识的名称，无需为命名再次询问；重名时加简短区分标记。默认创建后，在首次保存确认中告诉用户实际目录，无需每轮重复。接续已有任务沿用原目录，不自动迁移。普通数学问答默认在对话中完成；共享中文参考与项目子目录并列，按其独立约定处理。

其他宿主按用户指定目的地及当前工作区的可用保存能力处理，并准确报告实际保存位置。用户明确要求云端而当前没有相应能力时，在当前可用位置保留完整、可恢复的成果，说明尚未完成云端保存及所缺条件，不把本地成果称为云端已保存，也不为目录命名反复询问。

研究项目继续使用同版本的数学主稿、计算草稿、只追加研究日志、下一次入口和参考资料台账五文件，以及 `download/`、`tmp/`、`old/`；职责、命名、命令和恢复步骤以 `references/research-workbench.md` 为准。必要代码、数据和证书可另存证据目录，不因五文件约定丢弃复现材料。

普通文稿使用独立控制稿与干净正文；中间轮默认保存正文、控制与必要资源，最终成品轮按交付目标制作同版 PDF，TeX 按需交付。来源、当前计划、偏好、构建及编辑记录集中在控制稿，正文与必要资源按 `references/working-draft.md` 保存。

文稿默认规划与已启动批次的接续按 `references/working-draft.md`；研究材料充分且已获启动时直接推进，不另加写作规划关卡。保存待启动计划不构成执行授权；收到执行指令后，在当前会话授权及宿主规则允许的范围内自主安排工作、委派和保存，不自行添加轮数限制或逐项批准关卡。用户明确的暂停、单轮与范围限制继续有效。文稿计划在控制稿，研究计划在下一次入口。

仅作翻译、文风编辑和成品处理时，使用明确的当前来源并保留版本。活动研究项目回研究工作台处理实质数学修订；普通来源则在已授权的数学修订范围内处理，范围尚不明确时再说明所需修改。语言与排版本身不暗中改变数学内容或结论状态；正常数学问答和研究仍可完成已授权的推导、证明与纠错。

修订时用程序完整复制可编辑来源后局部修改，不让模型重新生成未变全文。可靠副本与已有核验按实际适用性复用。候选和构建材料放 `tmp/`，确认新版完整保存后才归档上一版；研究日志只追加。实际保存位置与流程见对应工作模组，本地脚本成功不等于远端保存成功。结构检查不能判断数学正确性。

## 向用户交付

研究汇报由主代理结合总目标与实际结果组织，优先说明本轮看清了什么、关键思路或方法，以及结果对研究的作用；按内容取舍，不规定每次逐项填写。保留影响判断的适用条件、关键核验结论和实际未决处，有价值的失败与条件性认识也可成为主要进展。

让读者无需记住内部记录就能理解：用数学内容代替内部定理代号，必要的局部符号首次出现时解释，不用未定义符号压缩叙述。完整证明、证据定位与路线记录留在可查文件中；简报从数学意义重新组织，不直接缩写最近日志。末尾交代经主代理判断的研究安排或阶段状态，不强制追加新任务。

简短确认实际保存结果。常规操作成功无需逐条声明未做事项或重复制度说明。不要把工具通过说成数学证明，也不要把参考稿或文献的发表身份说成具体命题已经验证。
